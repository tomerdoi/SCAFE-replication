# ScaBench usage-terms stop decision — 9 November 2026

## Decisive new result

Stop the present Code4rena-derived ScaBench training/evaluation route. Published
Code4rena terms section 8(g) restrict automated content access, and section 8(h)
restrict model training, evaluation and derived model-use datasets without separate
written authorization. No applicable authorization is established here. ScaBench's
repository MIT notice does not demonstrate permission to reuse underlying reports
or submissions for the intended model task. This is a conservative research-data
admission hold, not a legal determination about all possible uses or source code.

Terms observed 9 November 2026, published effective date 7 January 2025:
https://docs.code4rena.com/legal/terms-of-service

The original public SecondSwap report H-02 exposes the same three immutable
repository/file/line pointers as the saved candidate, strengthening the narrow
original-report provenance chain. It does not validate exploitability or qualify
an independent evaluation example. The original submission detail requires login;
no login/access bypass was attempted. The pinned GitHub tree page failed retrieval
and was not retried. Separately hosted source displays an MIT SPDX header, which
does not extend to report annotations or prove import/license completeness.
After discovering the report terms, further collection/mapping was stopped. No
contract source corpus, archive, model or report body was downloaded locally; no
remote code was executed. Browser inspections and their limits remain recorded.

Original report: https://code4rena.com/reports/2024-12-secondswap

## Effect on the prospective task

Reuse of the prior aggregate platform counts establishes that **all 37 declared-
revision-matched development findings, seven projects and 62 candidate location
links are Code4rena-derived**. The 24 Solidity findings / four projects are also
within that held scope. The prior development pool has 13 Code4rena projects /
250 findings; the other six projects (one Cantina, five Sherlock; 63 findings)
had zero established matching immutable links. No reserve finding was inspected,
recounted or used to rescue the design. No model training/evaluation rows or gold
labels were created, and the old canonical labels, masks and splits remain intact.

Thus the current route has zero established revision-matched findings outside the
held scope, not a ready seven-project benchmark. Independent sponsor source may
have different terms, but cannot inherit the report's labels or become labeled
training/evaluation data through this workaround. Do not rehost, paraphrase, embed
or extract features from held content for model use to evade the restriction.
Previously collected metadata remains preserved for restricted provenance/admission
recordkeeping; retaining it is not permission to train/evaluate from it.

## Pivot and next outcome

The previous two-session feasibility screen has now produced a stop decision for
this candidate route. Repeating source mapping, licensing inventories or model
experiments on the held material cannot close the gate. The next bounded milestone
is one real public source with explicit applicable annotation and code terms plus
an immutable original finding-to-source chain and an adequate review universe.
A Cantina/Sherlock candidate must independently pass these gates; neither is admitted
by association with ScaBench, and its uninspected reserve must stay uninspected.
If no credible alternative closes within the next two bounded sessions, revise the
research question/evidence package explicitly rather than extend the same curation
plan. Qualified evaluation, grouping, fair baselines and uncertainty remain required.
The conditional November manuscript windows are not commitments; this failed data
route is a concrete dependency delaying milestone 1, not an accuracy improvement.
