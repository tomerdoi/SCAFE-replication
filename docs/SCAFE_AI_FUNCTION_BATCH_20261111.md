## Actual AI decisions and units

The AI read the entire bound library and five functions under the existing explicit
three-category, three-axis review rubric. The target is pattern_presence, separate
from contextual_suspicion and supported_vulnerability. Source susceptibility/concern
labels are not the same target and remain unchanged. Pattern definitions are:
reentrancy control-transfer/state relevance; unchecked low-level success-result
handling; and authorization-sensitive asset/privilege/configuration operations,
not automatically an absent guard or exploitable vulnerability.

| Unique functions | Reentrancy pattern | Unchecked-call pattern | Authorization-sensitive operation |
| --- | --- | --- | --- |
| _uniswapLess, _uniswapMore | Absent | Absent | Absent |
| getUniV2PathWithPriceOut, getUniV2PathWithPriceIn, _getPathWithPrice | Unknown | Unknown | Absent |

The two pure comparison bodies only read memory arrays and compare values; those
six narrow absence proposals are based on complete bodies, not missing findings.
The three view quote/path routines add three operation-pattern absence proposals;
external callback/dependency-sensitive categories stay unknown rather than inferring
security from view, typed calls or empty catch blocks. All contextual-suspicion and
supported-vulnerability axes remain unknown because no complete caller/dependency,
policy or exploitability review was performed. These are not blanket safe functions.
